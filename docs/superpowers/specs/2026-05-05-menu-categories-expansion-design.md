## Что делает план реализации (в writing-plans)

1. **Шаг A — категории.** Через Directus REST API создать 2 новые категории (`breakfast`, `snacks`) с `status=published`, `sort=4` и `5`. Обновить `sort` у `ready-meals` (6) и `frozen` (7). Обновить `subtitle` у `drinks`.
2. **Шаг B — товары.** Батч-создать 35 новых записей в `products` (минимально обязательные поля: `slug`, `title`, `price`, `category`, `status=published`). Поля `description`, `image`, `gallery`, `popularity_rank` — не заполняем, редактор внесёт через CMS.
3. **Шаг C — ревалидация.** Дёрнуть `/api/revalidate` фронтенда (Next.js ISR) — секрет в `deploy/.env`.
4. **Шаг D — smoke-test.** Через `curl` к публичному API (`?fields=*` без токена) проверить, что 8 категорий и 58 товаров видны без авторизации; зайти на frontend (`/menu`, `/category/breakfast`, `/category/snacks`) — проверить рендер.
5. **Шаг E — TODO-чек редактору.** В коммит-сообщение / PR-описание включить чек-лист: загрузить картинки для категорий `breakfast` и `snacks`, проставить реальные цены 7 товаров с `price=1`.

## Технические детали для реализации

- **Endpoint:** `https://delovkusa.openlabio.ru/directus`
- **Auth:** `DIRECTUS_ADMIN_TOKEN` из `.env.local` (Bearer-токен)
- **Permissions:** для роли Public должно работать чтение `categories` и `products` (уже настроено по логам последних коммитов).
- **Идемпотентность:** перед `POST` плану следует `GET ?filter[slug][_eq]=...` чтобы не плодить дубли при повторном прогоне.
- **SSH (192.168.1.166):** не требуется для этой задачи — всё делается через REST API. SSH остаётся «на всякий случай» для диагностики Caddy / контейнеров, если что-то не отзовётся.
